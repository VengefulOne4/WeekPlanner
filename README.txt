НЕДЕЛЬНОЕ РАСПИСАНИЕ — ДЕСКТОПНАЯ ВЕРСИЯ
==========================================

Файлы (должны лежать в одной папке):
  - desktop_app.py       — запускающий скрипт + логика обновлений
  - weekly_planner.html  — само приложение (вёрстка + логика)
  - version.json         — текущая версия приложения
  - .gitignore

УСТАНОВКА
---------
Нужен Python 3.8+, библиотека pywebview и Git.

    pip install pywebview --break-system-packages

Если команда pip не работает, попробуйте pip3.

Дополнительно по ОС:
  Windows — использует Edge WebView2. На Windows 11 и свежей Windows 10 он
            обычно уже встроен. Если его нет, кнопка "Проверить обновления"
            (и вообще связь между окном и Python-кодом) не будет работать —
            поставьте "WebView2 Runtime" с сайта Microsoft:
              https://developer.microsoft.com/microsoft-edge/webview2/
            (нужен "Evergreen Bootstrapper", самый простой вариант).
  macOS   — работает из коробки (системный WebKit).
  Linux   — может понадобиться пакет с WebKit2GTK, например (Ubuntu/Debian):
              sudo apt install python3-gi gir1.2-webkit2-4.0

ЗАПУСК
------
    python desktop_app.py

Если кнопка "Проверить обновления" пишет, что мост к приложению не отвечает —
это почти всегда WebView2 Runtime отсутствует на Windows (см. выше). Окно
запускается с debug=True, поэтому можно нажать правой кнопкой мыши по окну
приложения → "Inspect" (или "Проверить") и посмотреть на вкладке Console,
что там с window.pywebview — так будет видно точную причину.


ПРОФИЛИ И ЛОКАЛЬНОЕ ХРАНЕНИЕ
------------------------------
В десктопной версии задачи, категории и ставка хранятся не в браузерном
localStorage, а в обычных JSON-файлах рядом с приложением, в папке
profiles/ (создаётся автоматически при первом запуске):

  profiles/index.json     — список профилей и какой сейчас активен
  profiles/<id>.json       — данные одного профиля (задачи, категории, ставка)

Кнопка "Профиль: ..." в панели инструментов открывает менеджер профилей —
там можно создать новый профиль, переименовать, переключиться между ними
или удалить (кроме последнего оставшегося). Каждый профиль полностью
независим: свои задачи, свои категории, своя ставка.

При самом первом запуске десктопной версии, если в браузерном localStorage
уже что-то было (например, вы тестировали приложение раньше), эти данные
один раз автоматически переносятся в профиль "По умолчанию".

ВАЖНО: папка profiles/ добавлена в .gitignore и НИКОГДА не должна
попадать в git — это ваши личные локальные данные, не код приложения.
Кнопка "Проверить обновления" тянет только код (HTML/JS/Python), профилей
она не касается и никогда их не перезапишет.

Если приложение запускается прямо в браузере (просто открыть
weekly_planner.html без desktop_app.py) — профили недоступны, данные
хранятся только в localStorage браузера, как раньше.

НАСТРОЙКА АВТООБНОВЛЕНИЯ ЧЕРЕЗ GIT
------------------------------------
Кнопка "Проверить обновления" в приложении делает `git fetch` / `git pull`
прямо в этой папке. Чтобы она заработала, папка должна быть git-репозиторием
с настроенным remote и upstream-веткой. Сделать это нужно один раз.

Шаг 1. Создайте пустой репозиторий на GitHub (без README, .gitignore и лицензии —
        они уже есть в этой папке). Скопируйте его URL, например:
          https://github.com/<ваш-логин>/weekly-planner.git

Шаг 2. Откройте терминал в этой папке и выполните:

    git init
    git add .
    git commit -m "Initial commit"
    git branch -M main
    git remote add origin https://github.com/<ваш-логин>/weekly-planner.git
    git push -u origin main

   (флаг -u важен — он и создаёт ту самую upstream-связь, без которой
    кнопка "Проверить обновления" не сможет понять, есть ли новые коммиты)

Шаг 3. Готово. Теперь при каждом запуске "Проверить обновления" в приложении
        сравнивает локальный код с тем, что лежит в репозитории на GitHub.

КАК ПУБЛИКОВАТЬ ОБНОВЛЕНИЯ
----------------------------
Когда вносите изменения (сами или через меня):

    1. Поднимите номер версии в version.json, например "1.0.1"
    2. git add -A
    3. git commit -m "Что изменилось"
    4. git push

После этого на любом компьютере, где запущено приложение с настроенным
git-репозиторием, кнопка "Проверить обновления" покажет, что есть новая
версия, и по подтверждению скачает изменения (git pull) и перезапустит
приложение — подтянутся изменения и в HTML/JS, и в самом desktop_app.py.

ВАЖНО
-----
- Если репозиторий приватный, git должен быть настроен на доступ без
  пароля в терминале (SSH-ключ или сохранённый токен/учётные данные) —
  иначе git pull внутри приложения зависнет на запросе логина.
- "git pull --ff-only" используется намеренно: если вы сами правили файлы
  в этой папке локально и они конфликтуют с обновлением, pull безопасно
  откажет вместо того, чтобы что-то сломать слиянием.
- Кнопка "Проверить обновления" на самом деле проверяет ДВЕ разные вещи:

  1. Отстаёт ли ваш локальный git-репозиторий от GitHub (актуально, когда
     изменения на GitHub появились НЕ из этой копии — с другого компьютера,
     из другой копии репозитория и т.п.). Если вы сами только что сделали
     commit и push прямо в этой же папке — тут по определению всё свежее,
     это не проверка файлов на диске.

  2. (Только для собранного .exe) Не устарела ли сама СБОРКА относительно
     исходников: version.json в папке проекта сравнивается с version.json,
     запечённым внутри текущего .exe при последней сборке. Это ловит именно
     случай "я отредактировал файлы локально и поднял версию, но .exe ещё
     старый" — не важно, был при этом git push или нет. Именно эта проверка
     решает задачу однокомпьютерного сценария: не нужно ничего пушить на
     GitHub, чтобы кнопка предложила пересобрать .exe — достаточно поменять
     файлы и version.json локально.

  Если сработало хотя бы одно из двух, кнопка предложит обновиться — и в
  диалоге подтверждения будет видно, какая именно причина сработала.

ЕСЛИ ВЫ ЗАПУСКАЕТЕ СОБРАННЫЙ .EXE
------------------------------------
Когда приложение запущено как .exe (а не через `python desktop_app.py`),
кнопка "Обновить" после `git pull` автоматически ПЕРЕСОБИРАЕТ .exe заново
через PyInstaller и перезапускает уже новую сборку. Это необходимо: .exe
запекает HTML/Python в себя в момент сборки, так что простой перезапуск
старого .exe показывал бы старый код, даже если git pull прошёл успешно.

Для этого на машине, где запускается .exe, должны быть постоянно
установлены Python, pywebview и pyinstaller (то есть именно те, что вы
ставили через pip install ... --break-system-packages) — пересборка
идёт от них. Процесс может занять от нескольких секунд до пары минут
(PyInstaller собирает всё заново) — приложение в это время может выглядеть
подвисшим, это нормально, дождитесь, пока окно перезапустится само.

Если пересборка не удастся (например, PyInstaller не найден в PATH),
кнопка покажет точную ошибку, а старая версия .exe продолжит работать
без изменений — ничего не сломается.

СБОРКА В .EXE С СОХРАНЕНИЕМ ОБНОВЛЕНИЙ
-----------------------------------------
Важно: используйте --onedir, а не --onefile. При --onefile программа при
каждом запуске распаковывает себя во временную папку (%TEMP%), которая
пересоздаётся заново и никогда не будет git-репозиторием — поэтому кнопка
обновления там гарантированно не работает. --onedir просто кладёт .exe и
файлы рядом, без временной распаковки.

    pip install pyinstaller --break-system-packages
    pyinstaller --onedir --add-data "weekly_planner.html;." --add-data "version.json;." desktop_app.py

(на macOS/Linux вместо ";." используйте ":.")

Готовая папка появится в dist/desktop_app/ — прямо ВНУТРИ вашего проекта
(F:/Projects/Weekly Planner/dist/desktop_app/). Это специально: git ищет
.git не только в текущей папке, но и во всех родительских, поэтому пока
dist/ остаётся внутри папки с репозиторием — обновления работают, даже
если запускать сам dist/desktop_app/desktop_app.exe.

Что нельзя делать: переносить dist/desktop_app/ в другое место (Downloads,
Рабочий стол, другой диск) — тогда рядом больше не будет .git, и кнопка
обновления снова начнёт писать "not a git repository". Если нужно раздать
приложение на другой компьютер без обновлений — тогда можно копировать
куда угодно, просто кнопка обновления там работать не будет.

Ярлык для запуска удобно класть где угодно (хоть на Рабочий стол) — важно
только сохранение самой папки dist/desktop_app/ внутри проекта.
